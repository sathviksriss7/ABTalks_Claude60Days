THE BRAIN — SYSTEM PROMPT DESIGN

QuickFit Coach is a single persistent Claude persona with a strict output contract. Every call — the initial plan generation and every chat refinement — sends the same system prompt plus the growing conversation history, so the model always knows the full session context (what it already prescribed, what the user has since asked to change).

  • Role & scope is narrowed on purpose: workout planning, exercise substitution, form cueing, and progression logic for busy adults. It's explicitly told not to give medical diagnoses, injury treatment, or precise calorie/macro numbers — those get a redirect to a doctor, physio, or dietitian instead of a confident-sounding guess.
  • Structured output contract: the model must reply with JSON only, matching a fixed schema (reply, sessionTitle, totalMinutes, warmup[], exercises[], cooldown[], assumptions[], safetyNote). This is what lets the interface render exercise cards and the session dial deterministically instead of trying to regex-parse prose.
  • Edge cases baked in: if inputs are irrelevant or nonsensical, the model asks for the missing piece inside reply rather than inventing a plan. If the user mentions pain or an injury, it downgrades intensity, adds a safetyNote, and suggests professional evaluation for anything beyond mild soreness. If someone tries to jailbreak it into unrelated tasks (coding, medical dosing, etc.), it stays in character and redirects to fitness. Abuse is met with one calm boundary-setting reply, not escalation.
  • Time-budget discipline: the model is instructed to keep warmup + working sets + cooldown within roughly 10% of the requested minutes — this is the single hardest constraint for a "busy professional" persona, so it's called out explicitly rather than left implicit.

WHY THE UI LOOKS LIKE THIS

The audience is time-poor, not fitness-illiterate — so the interface leads with a Session Dial: a stopwatch-style radial gauge that visually splits the session into warmup / work / cooldown arcs, because "how is my time being spent" is the first question a busy person asks, before they even read exercise names. Chips replace dropdowns everywhere so setup takes seconds, not typing. Exercise cards use a left-edge color bar (yellow/coral/mint) that echoes the dial's own legend, so the whole page reads as one time-budget system rather than a form bolted onto a list.

The refine panel is a lightweight chat rather than a full rebuild button, because real adjustments ("swap this," "shave 10 minutes," "no jumping") are conversational edits, not new sessions — and quick-refine chips surface the most common ones with zero typing.

THE OUTPUT CONTRACT (JSON SCHEMA)

{
  "reply": "short energetic coach line",
  "sessionTitle": "string",
  "totalMinutes": 30,
  "assumptions": ["string", ...],
  "safetyNote": "string or empty",
  "warmup":   [{ "name","duration","cue" }],
  "exercises":[{ "name","sets","reps","rest","equipment","intensity","cue" }],
  "cooldown": [{ "name","duration","cue" }]
}

HOW TO EXTEND THIS

  • Progress tracking: persist completed sessions (localStorage in a real deploy, or a backend) and feed a short history summary into the system prompt so the coach can reference "last time you did 3x10 push-ups" and auto-progress load/reps.
  • Tools / MCP: connect a calendar MCP server so the coach can check how much free time actually exists today before proposing a session length, or a wearables API to factor in sleep/recovery data.
  • Multi-step flows: add a "Week Plan" mode that calls the model once to generate a 5-day split, then treats each day as its own mini-session using this same card renderer.
  • Voice/rest timer: wire the rest field on each exercise card to an actual countdown timer component with audio cues for hands-free use mid-workout.
  • Personalization memory: store injury notes and equipment across sessions so returning users skip setup entirely and land straight in a pre-filled dial.
